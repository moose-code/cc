## checked, no finding

- eth leaves the Core only through its doors: `_sellForEth` pays the bid read of the booked pot per credit and reverts the whole batch when the pot runs out; `buyListing` pays `value + paid` with `value <= bid <= ethPot` and `paid <= bid - value`; `sellTo` and `sellCreditTo` move eth only into pots; `buyback` spends at most `slice - maxPay` through the pool manager and books the rest back; `_payCaller` is capped by the settings bounds and the pot; `claimPayee` pays only `payeeOwed`; `migrate` sends `ethPot` to the successor through `fund()` or a plain send; `collectEscrow` and `fund` only add.
- the owner takes nothing beyond the accepted powers: the owner functions move assets only to the successor (`migrate`), rescue untracked coin and NFTs, and set prices. `rescueNft` refuses a credit in the pile and a held statement.
- a credit is never bought above the bid: `_bid()` is `min(price state, ethPot)` after `_book`; `buyListing` checks `value > bid`; the cost basis `value + paid` is at most the bid.
- a statement never leaves below the floor: `sellTo` requires `msg.value >= cost * saleFloorBps / 10_000`; the controller's curve floors at `saleFloorBps` of the reference, which is at least the cost. `redeemStatement` requires the balance delta `>= rating * unit * (10_000 - redeemSlippageBps) / 10_000` with the unit read in the call, and `_unhold` runs before the external calls.
- fees reach the pot by themselves: every door starts with `_book()` (through `_openDoor` or directly: `sellTo`, `sellCreditTo`, `redeemStatement`, `buyback`, `fund`, `collectEscrow`, `setSettings`); `book()` is permissionless; `_income` subtracts `msg.value` so a payable door never counts its own payment as fees; `payeeOwed` is in the tracked sum, so a claim pending is never re-shared.
- only fees are shared: `receive` accepts the hook and the escrow only, so every eth that reaches the balance outside a payable door came from the pool or the escrow. a stray external `escrow.claim(core, 0)` lands as fee income at the next book (documented).
- no door is bricked by a counterparty: the controller reads are bounded staticcalls with fixed gas (`nextPage` 500,000, `atFloor` 400,000, `pastWindow` 200,000) and a failure reads as not ready, not eligible or not past the window; the adapter quote is bounded (300,000 gas, 8,192 bytes); the module's unit read is bounded in both the Core and the controller and a bad read reverts `BadModule` in the doors and yields 0 in the controller's pool term; a reverting payee or royalty recipient blocks only its own claim; a successor without `fund()` takes a plain send.
- pots never exceed the balance: every increase of a pot is matched by eth that arrived (`_book` books only `balance - tracked`, `fund` books `msg.value`, `sellTo` and `sellCreditTo` book `msg.value`, `collectEscrow` books the measured delta) and every decrease is matched by an outflow or a move between pots.
- reentrancy: every state changing Core door is `nonReentrant` on solady's guard; the library doors (`rescueCoin`, `rescueNft`, `migrate`) take the same guard slot through `_enter`/`_leave`; `receive` is a sender compare with no state; `onERC721Received` is a view; the controller's `buy`, `buyCredit` and `buyCredits` hold `_busy` across the Core call and the refund; `claimRoyalty` zeroes before sending. a reentry from Seaport, the strategy, the hook push, the module's `redeem`, a payee or a successor into any door reverts `Reentrancy`.
- the library and the layout: the Core declares one variable, `State internal s`, at slot 0, and the library reads the same type at slot 0; solady's guard uses a fixed slot outside the struct; `test/CoreLayout.t.sol` compares every field with raw storage; `setSettings` rebuilds the calldata under the library's selector with the same argument layout.
- the CREATE2 deploy: the Core's init code excludes the controller and the adapters, so its address is a function of the config and the deployer salt; the controller and the Seaport adapter embed the Core address; a pre deploy of the same init code by a stranger produces the same contract (the owner is a constructor argument from the config) and the deploy skips it; the launch config carries the Core as bounty recipient and `_launch` checks the coin against the Core's `COIN`. before `setController` the doors fail closed (`compose` NotReady, `sellTo` OnlyController); `sellForEth` and `fund` work with an empty pot, which pays nothing.
- the pause clock: `pausedNow() - pauseMark` never exceeds `block.timestamp - composedAt` because both grow from the compose at most one second per second; `setPaused` repeated is a no op.
- `pointRate`, `valueOf` and the pool math: `mulDiv(floorRate, points, refScore)` multiplies before dividing; the pool term checks `points * unit` for overflow and both `mulDiv` quotients for 256 bits and returns 0 instead of reverting; a unit above `uint128.max` reads as a failed read in the controller and `BadModule` in the Core doors.
- the royalty: `buy` takes `price + royalty`, forwards `price` to `sellTo`, adds the royalty to `royaltyOwed` after the Core call, refunds `msg.value - gross` last; `buyCredits` sums per credit; the anchor moves on `price`.
- the balance side gates: `redeemStatement` requires a module and `redeemOn`; `sellForBalance` requires `balanceBidOn`, `retired` false, a module, and reverts `BadModule` or `BadQuote` on a bad unit or `refScore` read; `setBalanceModule` keeps the token fixed and refuses a forbidden module or token.
- the adapters: the Seaport adapter accepts only the two open ETH to ERC721 routes (zone ignored), the Credits token, the exact `id`, amount 1, native consideration, and every additional recipient the offerer or allowlisted; `value` is the exact sum, so Seaport refunds nothing (a refund would come from Seaport, which `receive` refuses, and the fulfillment would revert); the NFT goes to the fulfiller, the Core. the strategy adapter reads `nftForSale(id)` and calls `sellTargetNFT(id)`, which takes the exact value.
- `migrate` and the retired engine: the first call sets `retired`; the six buying and composing doors refuse; the sale, redeem, buyback, book and owner doors keep working; `ethToBuyback` and `ethRedeemBurn` stay; the balance token leg logs and continues on failure.
- gas bounds: every bounded read has a fixed cap; the transaction cap test in test/GasCap.t.sol pins compose, redeem, buyListing through both adapters, buyback and a 115 credit `sellForEth`.
